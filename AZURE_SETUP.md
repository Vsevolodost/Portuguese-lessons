# Подключение Azure Speech к Bora

Подготовлено: серверная озвучка pt-BR-FranciscaNeural и распознавание коротких записей pt-BR / ru-RU. ГигаЧат продолжает отвечать за беседу и объяснения. Подключение активируется после добавления двух переменных и новой публикации на Vercel.

## Что нужно сделать владельцу

1. В [Azure Portal](https://portal.azure.com/) создать ресурс **Speech / Azure AI Speech**. Если предлагается бесплатный тариф **F0**, выбрать его для пилота. Если доступен только платный тариф, сначала проверить стоимость и настроить бюджет в Azure.
2. В ресурсе открыть **Keys and Endpoint**. Понадобятся один ключ и точный код региона, например `westeurope`. Регион должен соответствовать ресурсу, а не месту проживания пользователя.
3. В [настройках Bora на Vercel](https://vercel.com/vsevolod-ost/portuguese-lessons/settings/environment-variables) добавить для **Production и Preview**:
   - `AZURE_SPEECH_KEY` — ключ ресурса, тип **Sensitive**.
   - `AZURE_SPEECH_REGION` — код региона ресурса.
4. Пароль Azure и данные карты не передавать. Ключ лучше вводить прямо в Vercel; в чат его присылать не нужно.
5. Сообщить «добавил». После этого нужна новая публикация и проверка настоящей озвучки и распознавания. Пока ключа нет, Azure не считается проверенным или подключённым.

Для локальной проверки эти же значения можно добавить в игнорируемый `.env`. Не включать их в GitHub и не добавлять префикс публичных переменных. Исходные файлы с ключом не публиковать.

## Поведение после подключения

- При наличии ключа и корректного региона `/api/config` возвращает только `speechProvider: azure`. Ключ и регион в браузер не передаются.
- `/api/speech`: сервер отправляет экранированный SSML в региональный Azure TTS; голос фиксирован на бразильском pt-BR-FranciscaNeural. Ответ — MP3.
- Микрофон: пользователь явно запускает запись. Браузер переводит её в WAV PCM 16 кГц, моно, 16 бит; максимум 30 секунд. `/api/transcribe` проверяет формат, вход в аккаунт и общий лимит, затем передаёт звук Azure STT. Распознанный текст показывается ученику до отправки ГигаЧату.
- Доступ требует Supabase JWT. Серверные вызовы озвучки и распознавания входят в существующие лимиты (6 запросов в минуту на ученика, 200 суммарно за сутки, 2 одновременно). Озвучка уже загруженной реплики повторяется из временного кеша страницы.
- Аудио в базу не сохраняется; оно кратковременно обрабатывается в памяти браузера и сервера. Для хранения и обработки самим Azure применяются условия Microsoft.
- ГигаЧат получает текст, а не звук. Оценка произношения и акцента не включена.
- Пока ключ и регион отсутствуют, продолжают работать прежняя серверная озвучка и распознавание браузера. Ошибка уже настроенного Azure не переключает запрос незаметно на другой сервис.

## Проверки

Автоматические тесты проверяют WAV, экранирование SSML, фиксированные адреса Microsoft и голос, авторизацию, квоты, обработку тишины, отсутствие ключа в публичном ответе, остановку микрофона при уходе со страницы. Настоящие вызовы Azure и проверка микрофона требуют ключа и устройства пользователя.

Официальная документация: [TTS REST](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/rest-text-to-speech), [STT для коротких записей](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/rest-speech-to-text-short), [поддержка языков и голосов](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/language-support).
